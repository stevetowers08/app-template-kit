# Latent UI

A gallery and shadcn registry (`@latent`) for the surfaces Latent Systems client apps and
AI OS apps use most: card headers, stat cards, tables, lists. Steve compares variants under
different looks, picks one per surface, and copies the recipe (registry item names) into
Claude Code in a new app. Background and the wider plan: vault
`Apps/Templates/App Design Playbook.md`.

## Where things live

| What | Where |
|---|---|
| Variant components + their metadata | `registry/latent/<surface>/` - `meta.ts` (pure data), `demos.tsx`, one `.tsx` per variant |
| Looks (colour, font, radius, shadow per client) | `registry/latent/looks/looks.ts` |
| Layout primitives (AppShell, Page, PageHeader, Stack/Inline) | `registry/latent/layout/` |
| Value formatting, `<Unmeasured />` | `registry/latent/lib/values.tsx` |
| Gallery app (not shipped) | `app/`, `components/gallery/`, `lib/gallery/` |
| Sample data (not shipped) | `lib/gallery/sample-data.ts` |
| Vendored registry code (not hand-edited) | `components/ui`, `components/reui`, `components/data-grid`, `components/data-table`, see `eslint.config.mjs` |

`registry.json`, `public/r/` and `app/looks.generated.css` are GENERATED by
`npm run registry` (runs automatically before `dev` and `build`) and are gitignored.

## Rules

- **Base UI, not Radix** (shadcn `base-nova`): use the `render` prop, never `asChild`. Dice UI
  publishes its data table and data grid for Base UI only, which is why.
- **Tokens only** in variants: semantic classes and `rounded-*` utilities, so every look
  applies. No hex/rgb/oklch literals. The global UI-primitives hook blocks hand-rolled
  primitives and hardcoded colours.
- **Unknown is null**: values are `number | null` and render with `<DisplayValue>` /
  `<Unmeasured />`, never `?? 0`. A delta exists only when `computeDelta` returns one.
- **One scroll owner**: `AppShell`'s `<main data-scroll-owner>`. A component that needs its
  own scroller (a sticky-header table region) documents it as a second owner in a comment.
- **Adding a variant**: add the entry to the surface's `meta.ts` (name starts with the
  surface), the component file, and the demo in `demos.tsx`. The `satisfies Record<Name,
  Demo>` there makes a missing demo a type error; `npm run registry` fails on a missing file.
- **Adding a look**: add it to `looks.ts` with values from a vault style page. Leave a token
  out rather than invent it; it then falls back to the neutral default.
- **Demos use `lib/gallery/sample-data.ts` only**, with fixed dates (`SAMPLE_NOW`), never `Date.now()`.

## Commands

- `npm run dev` - gallery at http://localhost:3210, and the registry at `/r/<name>.json`.
- `npm run verify` - registry build, typecheck, lint, production build. Run before committing.
